# 02. Сервер DB — 192.0.2.128

Выполнять на `prodcast-db-01.example.internal` после главы 01. Здесь размещаются три базы PostgreSQL и общий Redis; App и Windows Workers используют разные учётные записи. Команды первоначального создания рассчитаны на пустые каталоги данных.

## 1. Подготовить каталоги и образы

```bash
sudo -i
set -euo pipefail
umask 077
source /root/prodcast-inbox/secrets.env
test ! -e /opt/prodcast/db/compose.yaml
install -d -m 0755 /opt/prodcast/db/{config,certs,data}
cd /opt/prodcast/db
cat > images.env <<'EOF'
POSTGRES_IMAGE=pgvector/pgvector:0.8.6-pg18-trixie@sha256:78bf48b801e792f99e3ac62b5036fd3876e9be48afda16c1e331af1c75ceb2ff
REDIS_IMAGE=redis:8.2.9-alpine@sha256:30abb90e62f14b737010746def3ba99cc79fe19dcdb3d37b41f21fc62e7da19d
EOF
source images.env
docker pull "$POSTGRES_IMAGE"
docker pull "$REDIS_IMAGE"
PG_UID=$(docker run --rm --network none --entrypoint id "$POSTGRES_IMAGE" -u postgres)
PG_GID=$(docker run --rm --network none --entrypoint id "$POSTGRES_IMAGE" -g postgres)
REDIS_UID=$(docker run --rm --network none --entrypoint id "$REDIS_IMAGE" -u redis)
REDIS_GID=$(docker run --rm --network none --entrypoint id "$REDIS_IMAGE" -g redis)
install -d -m 0700 -o "$PG_UID" -g "$PG_GID" data/postgres
install -d -m 0700 -o "$REDIS_UID" -g "$REDIS_GID" data/redis
install -m 0644 /root/prodcast-inbox/ca.crt certs/ca.crt
install -m 0644 /root/prodcast-inbox/postgres.crt certs/postgres.crt
install -m 0600 -o "$PG_UID" -g "$PG_GID" /root/prodcast-inbox/postgres.key certs/postgres.key
install -m 0644 /root/prodcast-inbox/redis.crt certs/redis.crt
install -m 0600 -o "$REDIS_UID" -g "$REDIS_GID" /root/prodcast-inbox/redis.key certs/redis.key
printf '%s' "$PG_ADMIN" > config/postgres-admin-password
chown "$PG_UID:$PG_GID" config/postgres-admin-password
chmod 0600 config/postgres-admin-password
docker image inspect "$POSTGRES_IMAGE" "$REDIS_IMAGE" > /root/prodcast-db-images.json
```

Эти инфраструктурные образы не входят в v0.2. При невозможности скачать указанный digest сначала доставить сохранённый образ из доверенного registry; автоматически переходить на `latest` нельзя. Значения UID/GID получаем из образов, потому что они отличаются у разных дистрибутивов.

## 2. Настроить PostgreSQL TLS и доступы

```bash
cat > config/postgresql.conf <<'EOF'
listen_addresses = '127.0.0.1,192.0.2.128'
port = 5432
unix_socket_directories = '/var/run/postgresql'
hba_file = '/etc/prodcast-config/pg_hba.conf'
password_encryption = 'scram-sha-256'
ssl = on
ssl_cert_file = '/etc/prodcast-certs/postgres.crt'
ssl_key_file = '/etc/prodcast-certs/postgres.key'
ssl_ca_file = '/etc/prodcast-certs/ca.crt'
ssl_min_protocol_version = 'TLSv1.2'
max_connections = 150
shared_buffers = '1GB'
timezone = 'UTC'
log_timezone = 'UTC'
log_connections = on
log_disconnections = on
log_min_duration_statement = 1000
EOF
cat > config/pg_hba.conf <<'EOF'
local   all          postgres                                 peer
local   all          all                                      reject
hostnossl all        all                 0.0.0.0/0            reject
hostnossl all        all                 ::/0                 reject
hostssl prodcast2    prodcast_app        192.0.2.23/32      scram-sha-256
hostssl license_db   license_app         192.0.2.23/32      scram-sha-256
hostssl prodcast_ai  prodcast_ai         192.0.2.76/32      scram-sha-256
hostssl prodcast2    prodcast_worker_01  192.0.2.21/32      scram-sha-256
hostssl prodcast2    prodcast_worker_02  192.0.2.85/32      scram-sha-256
host    all         all                 0.0.0.0/0            reject
host    all         all                 ::/0                 reject
EOF
chmod 0644 config/postgresql.conf config/pg_hba.conf
```

App-контейнеры выходят на DB через NAT своего хоста `.23`. Проверить это по `pg_stat_activity.client_addr`. Если инфраструктура маршрутизирует контейнерные адреса напрямую, правила должны отражать фактический источник; не расширять HBA до всей сети без разбора.

## 3. Настроить Redis TLS и ACL

```bash
cat > config/redis.conf <<'EOF'
bind 127.0.0.1 192.0.2.128
protected-mode yes
port 0
tls-port 6380
tls-cert-file /etc/prodcast-certs/redis.crt
tls-key-file /etc/prodcast-certs/redis.key
tls-ca-cert-file /etc/prodcast-certs/ca.crt
tls-auth-clients no
aclfile /etc/prodcast-config/users.acl
dir /data
appendonly yes
appendfsync everysec
save 900 1
save 300 10
maxmemory 2gb
maxmemory-policy noeviction
logfile ""
EOF
python3 - <<'PY'
import hashlib, pathlib, shlex
s = {}
for line in pathlib.Path('/root/prodcast-inbox/secrets.env').read_text().splitlines():
 k,v = line.split('=',1); s[k] = shlex.split(v)[0]
password = lambda k: '#'+hashlib.sha256(s[k].encode()).hexdigest()
commands = ('ping hello auth select client|setname client|setinfo quit '
 'get set setex psetex mget mset del exists expire pexpire ttl pttl '
 'incr incrby decr decrby lpush rpush lpop rpop brpop blpop llen lrange lrem '
 'sadd srem smembers scard hset hget hgetall hdel hlen hincrby '
 'zadd zrem zrange zrangebyscore zrevrangebyscore zscore zcard '
 'publish subscribe psubscribe unsubscribe punsubscribe '
 'multi exec discard watch unwatch eval evalsha script|load')
lines = ['user default off',
 'user db_admin on '+password('REDIS_ADMIN')+' ~* &* +@all',
 'user prodcast_app on '+password('REDIS_APP')+
 ' ~* &* +@all -config -acl -debug -module -shutdown -flushall -flushdb -replicaof -slaveof -migrate']
for n in ('01','02'):
 patterns = '~workflows* ~scenarios* ~_kombu.binding.* ~*celery.pidbox* ~celery-task-meta-* ~worker'+n+'.* ~celeryev*'
 lines.append('user prodcast_worker_'+n+'_scheduler on '+password('REDIS_W'+n)+
              ' '+patterns+' &* -@all '+' '.join('+'+c for c in commands.split()))
pathlib.Path('config/users.acl').write_text('\n'.join(lines)+'\n')
PY
chmod 0644 config/redis.conf
chown "$REDIS_UID:$REDIS_GID" config/users.acl
chmod 0600 config/users.acl
```

`port 0` отключает Redis без TLS. Клиентские сертификаты не нужны: TLS проверяет сервер, ACL аутентифицирует пользователя. У каждого Worker свои служебные `worker01.*` / `worker02.*` ключи. При `NOPERM` проверить `ACL LOG`; не выдавать Worker `+@all` как обход ошибки.

## 4. Ограничить сеть до запуска

На этой схеме DB-контейнеры используют host network; ограничение входящих соединений работает в INPUT. Следующие правила добавляют отдельную цепочку и не сбрасывают существующие SSH-правила. Если firewall централизованно управляется, внести эквивалентные правила туда, не создавать второго владельца firewall.

```bash
iptables -N PRODCAST-DB-IN
iptables -A PRODCAST-DB-IN -i lo -j ACCEPT
iptables -A PRODCAST-DB-IN -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A PRODCAST-DB-IN -s 192.0.2.23 -j ACCEPT
iptables -A PRODCAST-DB-IN -s 192.0.2.21 -j ACCEPT
iptables -A PRODCAST-DB-IN -s 192.0.2.85 -j ACCEPT
iptables -A PRODCAST-DB-IN -s 192.0.2.76 -p tcp --dport 5432 -j ACCEPT
iptables -A PRODCAST-DB-IN -j DROP
iptables -I INPUT 1 -p tcp -m multiport --dports 5432,6380 -j PRODCAST-DB-IN
netfilter-persistent save
systemctl enable netfilter-persistent
```

Это начальное создание, не блок для повторного добавления дубликатов. После перезагрузки проверить `iptables -S PRODCAST-DB-IN`. PostgreSQL и Redis привязаны к IPv4-адресам; дополнительно убедиться через `ss`, что эти порты не слушают `[::]`.

## 5. Создать Compose и запустить

```bash
cat > compose.yaml <<'EOF'
name: prodcast-db
services:
  postgres:
    image: ${POSTGRES_IMAGE:?}
    network_mode: host
    environment:
      POSTGRES_USER: postgres
      POSTGRES_DB: postgres
      POSTGRES_PASSWORD_FILE: /etc/prodcast-config/postgres-admin-password
      POSTGRES_INITDB_ARGS: --auth-local=peer --auth-host=scram-sha-256
      PGDATA: /var/lib/postgresql/data/pgdata
    command: [postgres, -c, config_file=/etc/prodcast-config/postgresql.conf]
    volumes:
      - ./data/postgres:/var/lib/postgresql/data
      - ./config:/etc/prodcast-config:ro
      - ./certs:/etc/prodcast-certs:ro
    restart: unless-stopped
    healthcheck:
      test: [CMD-SHELL, pg_isready -h /var/run/postgresql -U postgres -d postgres]
      interval: 10s
      timeout: 5s
      retries: 20
    logging:
      driver: json-file
      options: {max-size: 10m, max-file: '5'}
  redis:
    image: ${REDIS_IMAGE:?}
    network_mode: host
    command: [redis-server, /etc/prodcast-config/redis.conf]
    volumes:
      - ./data/redis:/data
      - ./config:/etc/prodcast-config:ro
      - ./certs:/etc/prodcast-certs:ro
    restart: unless-stopped
    logging:
      driver: json-file
      options: {max-size: 10m, max-file: '5'}
EOF
dcdb() { docker compose --env-file images.env -f compose.yaml "$@"; }
dcdb config --quiet
dcdb up -d --wait
dcdb ps
dcdb logs --tail=50 postgres redis
ss -lnt | grep -E ':(5432|6380|6379)\b'
```

PostgreSQL должен быть healthy, Redis — running без ошибок ACL/TLS. На 6379 слушателя нет. `--wait` без Redis healthcheck не доказывает его готовность: выполнить проверку из шага 7.

## 6. Создать роли и базы

Выполнить **один раз**; парольные переменные берутся из защищённого inbox. При существующей роли команда намеренно завершится ошибкой.

```bash
dcdb exec -T --user postgres postgres psql -v ON_ERROR_STOP=1 -d postgres <<EOF
CREATE ROLE prodcast_app LOGIN PASSWORD '$PW_APP' NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE ROLE license_app LOGIN PASSWORD '$PW_LICENSE' NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE ROLE prodcast_ai LOGIN PASSWORD '$PW_AI' NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE ROLE prodcast_worker_01 LOGIN PASSWORD '$PW_W01' NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE ROLE prodcast_worker_02 LOGIN PASSWORD '$PW_W02' NOSUPERUSER NOCREATEDB NOCREATEROLE;
CREATE DATABASE prodcast2 OWNER prodcast_app;
CREATE DATABASE license_db OWNER license_app;
CREATE DATABASE prodcast_ai OWNER prodcast_ai;
REVOKE ALL ON DATABASE prodcast2 FROM PUBLIC;
REVOKE ALL ON DATABASE license_db FROM PUBLIC;
REVOKE ALL ON DATABASE prodcast_ai FROM PUBLIC;
GRANT CONNECT ON DATABASE prodcast2 TO prodcast_app, prodcast_worker_01, prodcast_worker_02;
GRANT CONNECT ON DATABASE license_db TO license_app;
GRANT CONNECT ON DATABASE prodcast_ai TO prodcast_ai;
EOF
for db in prodcast2 license_db prodcast_ai; do
  dcdb exec -T --user postgres postgres psql -v ON_ERROR_STOP=1 -d "$db" \
    -c 'REVOKE CREATE ON SCHEMA public FROM PUBLIC;'
done
dcdb exec -T --user postgres postgres psql -v ON_ERROR_STOP=1 -d prodcast_ai \
  -c 'CREATE EXTENSION IF NOT EXISTS vector;'
```

Пароли в примере hex, поэтому безопасны для SQL-литералов. При использовании произвольных паролей из другого хранилища не подставлять их в SQL этим способом без экранирования. Схему приложения создаёт App при миграции. База AI и расширение подготовлены, но RAG пока выключен; таблицы и документы для RAG сами от этого не появляются.

## 7. Проверить БД и Redis

```bash
dcdb exec -T --user postgres postgres psql -d postgres -c '\l'
dcdb exec -T --user postgres postgres psql -d postgres -c '\du'
dcdb exec -T --user postgres postgres psql -d postgres -c 'SHOW ssl;'
dcdb exec -T --user postgres postgres psql -d postgres \
  -c 'SELECT line_number,error FROM pg_hba_file_rules WHERE error IS NOT NULL;'
dcdb exec redis redis-cli --tls --cacert /etc/prodcast-certs/ca.crt \
  -h 127.0.0.1 -p 6380 --user db_admin --askpass PING
```

Для Redis интерактивно ввести `REDIS_ADMIN` из хранилища. Ожидается `PONG`, `ssl=on`, нет HBA errors, все пять прикладных ролей без superuser. Не выводить `secrets.env` в общий журнал. На этом этапе перейти к AI и App; права Workers выдаются после миграций App.

## 8. Права Workers после миграций App

Вернуться на DB после главы 04, шага 9. В новом терминале снова определить `dcdb` из шага 5 и перейти в `/opt/prodcast/db`.

```bash
dcdb exec -T --user postgres postgres psql -v ON_ERROR_STOP=1 -d prodcast2 <<'SQL'
BEGIN;
GRANT USAGE ON SCHEMA public TO prodcast_worker_01, prodcast_worker_02;
GRANT SELECT ON
 apiapp_unit_system, apiapp_unit_type, apiapp_unit_definition,
 apiapp_unit_category, apiapp_unit_system_category_definition,
 apiapp_workflow, apiapp_workflow_scheduler, apiapp_data_source_component,
 apiapp_scenarios, apiapp_scenario_component_link, apiapp_data_source,
 apiapp_object_type, apiapp_object_instance, apiapp_object_type_property
 TO prodcast_worker_01, prodcast_worker_02;
GRANT SELECT (id,username) ON auth_user TO prodcast_worker_01, prodcast_worker_02;
GRANT SELECT,INSERT,UPDATE ON apiapp_workflow_run TO prodcast_worker_01, prodcast_worker_02;
GRANT INSERT ON apiapp_audit_log TO prodcast_worker_01, prodcast_worker_02;
GRANT SELECT,INSERT ON apiapp_scenariolog,apiapp_workflow_scheduler_log TO prodcast_worker_01, prodcast_worker_02;
GRANT UPDATE (status,start_date,end_date) ON apiapp_scenarios TO prodcast_worker_01, prodcast_worker_02;
GRANT SELECT,INSERT,UPDATE,DELETE ON apiapp_mainclass,apiapp_mainclass_history TO prodcast_worker_01, prodcast_worker_02;
GRANT UPDATE (id) ON apiapp_data_source_component TO prodcast_worker_01, prodcast_worker_02;
GRANT USAGE,SELECT ON SEQUENCE
 apiapp_workflow_run_id_seq,apiapp_audit_log_id_seq,apiapp_scenariolog_id_seq,
 apiapp_workflow_scheduler_log_id_seq,apiapp_mainclass_data_set_id_seq,
 apiapp_mainclass_history_id_seq TO prodcast_worker_01,prodcast_worker_02;
COMMIT;
SQL
```

Если имя таблицы/sequence отсутствует, транзакция откатится. Проверить совпадение версии и выполненные миграции, `\dt apiapp_*` и `\ds apiapp_*`; не выдавать `ALL ON ALL TABLES`. `UPDATE(id)` нужен для блокировки строки компонента при записи результатов. Учётные записи Workers не должны читать password hashes `auth_user`, менять схему или создавать роли.

После запуска всех клиентов проверить действующие TLS-сессии:

```bash
dcdb exec -T --user postgres postgres psql -d postgres -c \
 'SELECT a.usename,a.datname,a.client_addr,s.ssl,s.version FROM pg_stat_activity a JOIN pg_stat_ssl s USING(pid) WHERE a.client_addr IS NOT NULL;'
```

Ожидаются App `.23`, Workers `.21`/`.85`, `ssl=t`. AI с выключенным RAG может не держать постоянного DB-соединения. Зафиксировать результат и переходить к Workers.
