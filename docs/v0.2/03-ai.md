# 03. Сервер AI — 192.0.2.76

Выполнять на `prodcast-ai-01.example.internal`. Требуются глава 01 и проверенные файлы AI из v0.2. DB должна быть подготовлена, но базовый AI без RAG не использует её для хранения документов.

## 1. Проверить GPU

```bash
sudo -i
set -euo pipefail
umask 077
nvidia-smi
```

Ожидается NVIDIA GPU, её память и версия драйвера, без ошибки связи с драйвером. Для VM GPU должен быть проброшен в гостевую ОС. Если драйвер ещё не установлен, установить поддерживаемый для GPU драйвер по процедуре Ubuntu/NVIDIA, перезагрузить и добиться успешного `nvidia-smi` **до** запуска модели. Установка Docker сама по себе драйвер не ставит. Ollama ниже работает на хосте, поэтому NVIDIA Container Toolkit для этой схемы не нужен.

На чистой Ubuntu с поддерживаемым GPU выполнить следующие команды **только если драйвера ещё нет**. `ubuntu-drivers` выберет поддерживаемый пакет для обнаруженного устройства; список кандидатов и фактическую версию сохранить. При Secure Boot завершить предложенное ОС подтверждение ключа модулей через консоль:

```bash
apt-get update
apt-get install -y ubuntu-drivers-common
ubuntu-drivers list --gpgpu
ubuntu-drivers install --gpgpu
reboot
```

После перезагрузки вновь войти, выполнить `sudo -i`, `set -euo pipefail`, `umask 077` и `nvidia-smi`. Если инструмент не предлагает совместимый пакет, остановиться на подготовке GPU. Основание: [установка драйверов NVIDIA в Ubuntu Server](https://ubuntu.com/server/docs/how-to/graphics/install-nvidia-drivers/).

## 2. Загрузить готовый ProdCast AI

На AI заранее доставлены файлы v0.2 и SHA256SUMS. Сборка не нужна:

```bash
cd /srv/prodcast-dist/v0.2
sha256sum --ignore-missing -c SHA256SUMS
test -s prodcast-ai-v0.2-linux-amd64.tar.gz
test -s prodcast-ai-v0.2-deployment.tar.gz
docker load -i prodcast-ai-v0.2-linux-amd64.tar.gz
install -d -m 0755 /opt/prodcast/ai/package /opt/prodcast/ai/certs
tar -xzf prodcast-ai-v0.2-deployment.tar.gz -C /opt/prodcast/ai/package
docker image inspect ghcr.io/saatchi190499/prodcast-ai:v2026.9.17-rc.1 \
  > /root/prodcast-ai-image.json
docker run --rm --network none --entrypoint sh ghcr.io/saatchi190499/prodcast-ai:v2026.9.17-rc.1 \
  -c 'test -z "$(find /app -name "*.py" -print -quit)" && python -c "from app.main import app; assert app"'
```

Ожидается linux/amd64, transport tag `v2026.9.17-rc.1`, успешный smoke. В `/opt/prodcast/ai/package` сохранены исходные Compose/examples, images.json, online/offline references. Ниже создаётся конкретная конфигурация с native Ollama и HTTPS на host network; она не требует изменений runtime image. Для повторной установки сохранить исходный архив v0.2 и его SHA256.

## 3. Установить Ollama отдельно от API

Бинарный runtime не входит в v0.2 или Python-репозиторий AI. В этой инструкции выбран Ollama `0.34.0`, Linux amd64. Его загрузка требует сети либо предварительной доставки архива.

```bash
cd /srv/prodcast-build
curl -fL https://github.com/ollama/ollama/releases/download/v0.34.0/ollama-linux-amd64.tar.zst \
  -o ollama-linux-amd64-0.34.0.tar.zst
printf '%s  %s\n' \
  cf95886728959aa09910bb34de5cca1cc5a8f68003b5597197d3f2c2d57c0804 \
  ollama-linux-amd64-0.34.0.tar.zst | sha256sum -c -
install -d -m 0755 /opt/ollama/0.34.0
tar --zstd -xf ollama-linux-amd64-0.34.0.tar.zst -C /opt/ollama/0.34.0
test -x /opt/ollama/0.34.0/bin/ollama
useradd --system --create-home --home-dir /var/lib/prodcast-ai --shell /usr/sbin/nologin prodcast-ollama
getent group video
getent group render
usermod -aG video,render prodcast-ollama
install -d -m 0750 -o prodcast-ollama -g prodcast-ollama /var/lib/prodcast-ai/models
cat > /etc/systemd/system/prodcast-ollama.service <<'EOF'
[Unit]
Description=ProdCast Ollama
After=network-online.target
Wants=network-online.target

[Service]
User=prodcast-ollama
Group=prodcast-ollama
SupplementaryGroups=video render
Environment=HOME=/var/lib/prodcast-ai
Environment=OLLAMA_HOST=127.0.0.1:11434
Environment=OLLAMA_MODELS=/var/lib/prodcast-ai/models
Environment=OLLAMA_NO_CLOUD=1
Environment=OLLAMA_NUM_PARALLEL=1
Environment=OLLAMA_CONTEXT_LENGTH=4096
ExecStart=/opt/ollama/0.34.0/bin/ollama serve
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
UMask=0027

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now prodcast-ollama
systemctl --no-pager status prodcast-ollama
curl -fsS http://127.0.0.1:11434/api/version
```

Если `video`/`render` отсутствуют, сначала проверить установленный драйвер и владельцев GPU devices; не пропускать эту ошибку. Структура установки и службы согласуется с [Ollama Linux](https://docs.ollama.com/linux); здесь использован отдельный каталог версии для отката.

## 4. Загрузить и проверить модель

```bash
OLLAMA_HOST=127.0.0.1:11434 /opt/ollama/0.34.0/bin/ollama pull qwen3:4b-instruct
curl -fsS http://127.0.0.1:11434/api/tags > /root/prodcast-ai-models.json
jq '.models[] | {name,digest,size}' /root/prodcast-ai-models.json
curl -fsS --max-time 180 http://127.0.0.1:11434/api/generate \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3:4b-instruct","prompt":"Reply with OK only.","stream":false,"keep_alive":"10m"}'
OLLAMA_HOST=127.0.0.1:11434 /opt/ollama/0.34.0/bin/ollama ps
nvidia-smi
```

Ожидается непустой ответ и использование GPU. Записать **фактический digest модели**, размер и время холодного ответа. Тег модели в удалённом registry может измениться; для воспроизводимости сохранить каталог моделей вместе с этим digest. Если модель недоступна или не помещается в память, установка AI ещё не завершена; подмена другой моделью требует новой функциональной проверки.

Offline-перенос: на подготовленной машине с той же Ollama скачать модель, остановить Ollama и архивировать весь её `OLLAMA_MODELS` (manifests и blobs); на AI распаковать в `/var/lib/prodcast-ai/models`, вернуть владельца `prodcast-ollama`, запустить службу и повторить тест. Одного имени модели или файла manifest недостаточно.

## 5. Создать конфигурацию API и TLS

```bash
cd /opt/prodcast/ai
source /root/prodcast-inbox/secrets.env
install -m 0644 /root/prodcast-inbox/ca.crt certs/db-ca.crt
install -m 0644 /root/prodcast-inbox/ai.crt certs/ai.crt
install -m 0600 -o 1000 -g 1000 /root/prodcast-inbox/ai.key certs/ai.key
cat > runtime.env <<EOF
APP_ENV=production
LOG_LEVEL=INFO
LLM_PROVIDER=ollama
LLM_MODEL=qwen3:4b-instruct
OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
LLM_TIMEOUT_SECONDS=90
AGENT_TIMEOUT_SECONDS=120
RAG_ENABLED=false
DATABASE_URL=postgresql://prodcast_ai:${PW_AI}@prodcast-db-01.example.internal:5432/prodcast_ai?sslmode=verify-full&sslrootcert=/etc/prodcast/certs/db-ca.crt
MCP_ALLOWED_SERVERS=
MCP_CODE_ENABLED=false
MCP_ENGINEERING_ENABLED=false
MCP_TEMPLATES_ENABLED=false
BROWSER_AUTH_USERNAME=prodcast-app
BROWSER_AUTH_PASSWORD_HASH=${AI_HASH}
NOTEBOOK_API_KEY=${AI_KEY}
EOF
chmod 0600 runtime.env
cat > compose.yaml <<'EOF'
name: prodcast-ai
services:
  api:
    image: ghcr.io/saatchi190499/prodcast-ai:v2026.9.17-rc.1
    pull_policy: never
    platform: linux/amd64
    user: '1000:1000'
    network_mode: host
    env_file:
      - path: ./runtime.env
        format: raw
    command: [uvicorn, 'app.main:app', --host, 192.0.2.76, --port, '8443', --ssl-certfile, /etc/prodcast/certs/ai.crt, --ssl-keyfile, /etc/prodcast/certs/ai.key]
    volumes:
      - ./certs:/etc/prodcast/certs:ro
    restart: unless-stopped
    security_opt: [no-new-privileges:true]
    mem_limit: 2g
    cpus: 2
    logging:
      driver: json-file
      options: {max-size: 10m, max-file: '5'}
EOF
docker compose config --quiet
```

В AI-образе пользователь имеет UID 1000, поэтому приватный TLS-ключ читается именно им. `runtime.env` читает root-процесс Compose, приложению передаются значения переменных. Не печатать полный `docker compose config`: он раскрывает секреты.

## 6. Ограничить доступ и запустить API

```bash
iptables -N PRODCAST-AI-IN
iptables -A PRODCAST-AI-IN -i lo -j ACCEPT
iptables -A PRODCAST-AI-IN -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A PRODCAST-AI-IN -s 192.0.2.23 -j ACCEPT
iptables -A PRODCAST-AI-IN -s 192.0.2.76 -j ACCEPT
iptables -A PRODCAST-AI-IN -j DROP
iptables -I INPUT 1 -p tcp --dport 8443 -j PRODCAST-AI-IN
netfilter-persistent save
docker compose up -d
docker compose ps
docker compose logs --tail=50 api
curl --fail --cacert certs/db-ca.crt https://prodcast-ai-01.example.internal:8443/health
ss -lnt | grep -E ':(8443|11434)\b'
```

API слушает `.76:8443`, Ollama только `127.0.0.1:11434`. Ожидается HTTP 200 `/health`. Это ещё не проверка модели через API.

## 7. Проверить notebook readiness и генерацию

```bash
cd /opt/prodcast/ai
python3 - <<'PY'
import json, pathlib, ssl, urllib.request, uuid
env = dict(line.split('=',1) for line in pathlib.Path('runtime.env').read_text().splitlines() if '=' in line)
ctx = ssl.create_default_context(cafile='certs/db-ca.crt')
base = 'https://prodcast-ai-01.example.internal:8443'
headers = {'X-API-Key':env['NOTEBOOK_API_KEY']}
req = urllib.request.Request(base+'/readyz', headers=headers)
with urllib.request.urlopen(req, context=ctx, timeout=120) as r:
 print(r.status, json.load(r))
cid = str(uuid.uuid4())
headers.update({'Content-Type':'application/json','X-Correlation-ID':cid})
data = {'goal':'Create Python code that prints 42.', 'current_code':'', 'context':{'correlation_id':cid}}
req = urllib.request.Request(base+'/v1/notebook/draft', data=json.dumps(data).encode(), headers=headers)
with urllib.request.urlopen(req, context=ctx, timeout=180) as r:
 result = json.load(r); print('Draft HTTP',r.status,'response keys:',sorted(result))
pathlib.Path('/root/prodcast-ai-draft-test.json').write_text(json.dumps(result,indent=2))
PY
```

`/readyz` должен вернуть `status: ready`, draft — HTTP 200 и осмысленный Python-код. Проверить файл ответа вручную, код автоматически не исполнять. `X-Correlation-ID` должен быть UUID и совпадать с `context.correlation_id`, иначе 422.

У chat `/api/chat` другой механизм: Basic Auth `prodcast-app` с паролем `AI_BASIC` (на AI его plaintext не хранится). Chat будет проверен с App после заполнения App `runtime.env`. 401 на notebook означает несовпадение `AI_KEY`; 503 readiness — недоступна модель; ошибки TLS — имя/SAN/CA; отсутствие GPU/медленный холодный старт — смотреть `journalctl -u prodcast-ollama` и `ollama ps`.

**Результат:** сохранены commit и image ID AI, checksum его архива, версия Ollama и digest модели; `/health`, `/readyz`, draft работают через проверенный TLS. Настройка RAG/индексация документов — отдельная работа, в этой конфигурации не включена.
