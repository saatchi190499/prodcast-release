# ProdCast v0.2 — ручное развёртывание production

Редакция: 22.09.2026. Для установки используются готовые файлы дистрибутива v0.2. Все дополнительные конфигурации и команды приведены в этих документах. Скрипты Windows runtime включены в сам Worker ZIP; доступ к рабочим каталогам разработчика или исходным репозиториям не требуется.

Это инструкция **первичной установки на подготовленные серверы**. Для существующей установки сначала выполнить раздел об обновлении и резервном копировании. Генерацию секретов, создание баз и первоначальное заполнение нельзя повторять поверх работающей системы.

## Что именно устанавливаем

| Сервер | Адрес в этой инструкции | ОС | Компоненты |
|---|---|---|---|
| DB — `prodcast-db-01.example.internal` | `192.0.2.128` | Ubuntu 26.04 amd64 | PostgreSQL 18 + pgvector, Redis с TLS |
| AI — `prodcast-ai-01.example.internal` | `192.0.2.76` | Ubuntu 26.04 amd64, NVIDIA GPU | Ollama, модель, ProdCast AI API |
| App — `prodcast-app-01.example.internal` | `192.0.2.23` | Ubuntu 26.04 amd64 | Gateway, Frontend, 8 API, Celery default/beat, License |
| Worker 01 — `PC-WORKER-01` | `192.0.2.21` | Windows Server 2025 x64 | `ProdCastWorker01`, Windows AppContainer |
| Worker 02 — `PC-WORKER-02` | `192.0.2.85` | Windows Server 2025 x64 | `ProdCastWorker02`, Windows AppContainer |

Адреса 192.0.2.0/24 и домен example.internal — обезличенные примеры, а не адреса действующей площадки. Этот диапазон предназначен для документации: перед установкой заменить его реальными адресами. Если площадка другая, заменить их **до начала работ** во всех конфигурациях, DNS, сертификатах и правилах доступа. Адрес административного компьютера в примере — `192.0.2.225`, DNS — `192.0.2.111`. Подсеть Docker App — `172.30.23.0/24`; проверить, что она не пересекается с сетью площадки/VPN.

Начальный ориентир ресурсов: DB 4 vCPU/8 GB RAM/200 GB, App 6 vCPU/12 GB/120 GB, AI 8 vCPU/12 GB/200 GB и GPU с 6 GB VRAM, каждый Worker 4 vCPU/8 GB. Это конфигурация начального запуска, не результат нагрузочного расчёта. До приёмки проверить реальные объёмы данных, потребление памяти и параллельные задания.

В v0.2 включены готовые App, Agent, AI, License и Windows Worker. Сборка из исходников для установки не требуется. Внутренние теги образов и версии EXE сохранены из исходных релизов; v0.2 — версия общего дистрибутива. Agent устанавливается на клиентский ПК и не заменяет Windows Worker.

Model Storage, NodeAll, RAG, Microsoft/LDAP и внешние PI-источники в данном профиле выключены. ОС, Docker/Compose, PostgreSQL/Redis, NVIDIA-драйвер, Ollama и модель поставляются/загружаются отдельно по инструкции: архив полного комплекта содержит все **пять приложений ProdCast**, но не все внешние инфраструктурные зависимости.

4. [Сервер App: образы, License, настройки, миграции](04-app.md), шаги 1–9.
5. Вернуться к [DB, шаг 8](02-db.md#8-права-workers-после-миграций-app): выдать права на уже созданные таблицы.
6. [Worker 01](05-worker-01.md).
7. [Worker 02](06-worker-02.md).
8. [App, шаг 10](04-app.md#10-запустить-единственный-планировщик): включить beat после проверки Workers.
9. [Agent на клиентском компьютере](08-agent.md), если нужен локальный запуск.
10. [Приёмка, резервное копирование, обновление и откат](07-operations.md).

Для Linux используются Bash и `sudo -i`; для Windows — повышенная PowerShell **в интерактивной сессии администратора**. Блоки выполнять по одному, проверяя результат. При ошибке не переходить к следующему шагу. Новый терминал требует повторного `cd`, объявления показанной функции Compose и загрузки нужных переменных.

Ни один этап не требует доступа к прежнему рабочему каталогу автора. Папки `/root/prodcast-inbox`, `/srv/prodcast-build`, `/opt/prodcast` и `C:\ProdCast` создаются администратором по этой инструкции.

## Основание и границы проверки документа

Параметры сверены с `runtime/compose.yaml`, `runtime.env.example`, `site.env.example`, `images.json` из архива v0.2; пакеты, Windows installer/service runner и API-контракты — с указанными тегами репозиториев. Дополнительные проверки перед запуском встроены в каждый раздел.

Эта редакция документа не является протоколом повторной чистой установки: приведённый маршрут целиком на новых серверах в ходе подготовки инструкции не выполнялся. Подписание акта — после проверок из главы 07.
