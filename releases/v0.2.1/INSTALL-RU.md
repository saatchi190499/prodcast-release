# ProdCast 0.2.1 — установка и обновление через Manager

Полный комплект: App v2026.9.23-rc.2, Agent v2026.9.19-rc.1, AI/License/Worker v2026.9.17-rc.1. Только App обновлён. Файлы AI, License, Worker и Agent побайтно совпадают с v0.2, имена файлов комплекта получили v0.2.1. Внутренние теги образов и версии программ сохраняются.

## Что скачать и проверить

Скачайте ProdCast-v0.2.1-complete.zip, его .sha256 и release-manifest.json.sha256 со страницы v0.2.1 в saatchi190499/prodcast-release. GitHub Source code не содержит установочных файлов. Сравните SHA256 ZIP с опубликованным значением; после распаковки SHA256SUMS проверяет все вложенные файлы. В PowerShell: Get-FileHash -Algorithm SHA256 .\ProdCast-v0.2.1-complete.zip.

Для поля Manager нужен SHA256 именно release-manifest.json, не внешнего ZIP. Сверьте его со значением в описании GitHub-релиза. Отдельный файл рядом с архивом без проверки источника не подтверждает подлинность.

## Обновление существующей установки v0.2

1. Используйте Manager 0.1.11 или новее с адаптером prodcast-five-vm-v1. Сохраните копию всей рабочей папки Manager, включая data/sites, secrets.json, secrets.key, SSH-ключи и журнал. Дождитесь завершения предыдущей операции.
2. Откройте исходный site.json этой установки. Не создавайте новую площадку и не меняйте адреса VM, ID, пароли, CA или сертификат PFX ради обновления.
3. На вкладке «Установка и обновление» выберите ProdCast-v0.2.1-complete.zip либо каталог с его release-manifest.json.
4. В поле «SHA256 manifest будущего релиза» вставьте опубликованный SHA256 release-manifest.json. Для v0.2.1 это обязательно: встроенный хеш v0.2 относится только к старому комплекту.
5. Выполните «Проверить доступ». Запланируйте окно обслуживания: Manager остановит приём запросов и расписания, дождётся завершения задач и остановит службы. Не создавайте новые задания в это время.
6. Нажмите «Обновить». Manager создаёт резервные копии перед миграциями, сохраняет существующие ключи и данные доступа, применяет пакеты и запускает службы по зависимостям. Хотя бинарные файлы остальных компонентов не изменены, общий сценарий обновления может перезапустить их службы.
7. Дождитесь «Готово» и отчёта status=complete. Проверяются PostgreSQL TLS, Redis, лицензия, ответ AI, оба Windows Worker и готовность App; затем запускается планировщик.
8. Проверьте вход в App, нужные пользователю workflows и расписания. Обновление добавляет миграцию apiapp.0042_schedule_output_policy с тремя полями политики сохранения результатов расписаний.

При ошибке сохраните data/sites и logs, устраните причину и повторите «Обновить» с тем же комплектом и хешем. После миграций автоматического отката БД нет. Не удаляйте контейнеры с данными, volumes, journal.json или secrets.key. Возврат образов к v0.2 сам по себе не отменяет миграцию.

## Первая установка

В новой площадке укажите пять VM и SSH-доступ, проверьте отпечатки. При необходимости импортируйте PFX. Выберите полный ZIP v0.2.1, введите SHA256 manifest и нажмите «Установить». Agent устанавливается отдельно на пользовательских ПК из включённого EXE. Manager размещает License вместе с App и готовит DB/AI на отдельных VM. Для AI обеспечьте реально доступную память для модели; минимум 8 ГБ на VM — практический ориентир для текущей модели на CPU. Наличие GPU не обязательно.

## Ручная установка и состав

Включены App deployment и три образа, AI deployment/образ, License deployment/образ, ZIP Worker с Python/WinSW/wheelhouse и EXE Agent. ОС, Docker/Compose, PostgreSQL/Redis, Ollama и модель не упакованы полностью offline: Manager готовит инфраструктуру с использованием сети.

ProdCast-v0.2-manual.html и ProdCast-v0.2-manual.zip оставлены как справочное руководство базовой топологии. При ручной установке используйте файлы с именами v0.2.1, App из нового deployment-архива и его images.json/packages.offline.env. У AI/License deployment внутренние документы v0.2 оставлены намеренно для сохранения исходных файлов. Не применяйте первичную инициализацию справочников и администратора к существующей базе.

## Проверки выпуска

Проверены SHA256 исходных assets, идентификаторы и платформа образов App, неизменность остальных компонентов, Compose и версии backend-зависимостей, адаптация gateway для PFX, загрузка полного ZIP реальным загрузчиком Manager и сценарий обновления с имитацией удалённых серверов. Полный переход v0.2 → v0.2.1 на пяти VM и функциональная приёмка нового App в рамках подготовки этого комплекта не выполнялись. Подробности в compatibility-validation.json. Работающие площадки при сборке релиза не обновляются.
