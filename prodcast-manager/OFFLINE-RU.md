# Офлайн-установка ProdCast v0.5.0-rc.2

1. Перенесите в локальную сеть complete ZIP (в нём уже есть Ollama) и, если нужен AI, файл модели Qwen3 4B Instruct. Дополнительный ZIP Ollama не нужен. Необходимые файлы можно заранее сохранить на носитель.
2. Сохраните ProdCast-Manager.exe в отдельный каталог с правом записи и запустите его. Для продолжения прежней установки импортируйте её site.json вместе с исходной папкой данных либо перенесите всю папку data рядом с новым EXE. Не создавайте новую площадку поверх существующей.
3. Укажите App, DB, от 1 до 16 Workers и, при необходимости, AI. Проверьте SSH-отпечатки. Для Linux нужен root либо sudo; для Workers — администратор Windows.
4. Импортируйте выданную офлайн-лицензию и публичный PEM подписи. Для нового развёртывания запросите лицензию на Installation ID, показанный Manager. Импортируйте PFX сайта и укажите его DNS-имя. Публичный CA должен быть доверенным на ПК пользователей.
5. Если нужен доменный вход, заполните LDAP / Active Directory и включите соответствующую галочку. Подробности — CHANGES-0.5-RU.md.
6. В первом поле выберите complete ZIP; рядом укажите SHA256 файла release-manifest.json. При включённом AI в третьем поле выберите файл модели. ZIP больше 2 ГБ поддерживается.
7. Проверьте доступ. Для чистых VM нажмите «Установить», для работающей площадки — «Обновить». После исправления ошибки повторяйте ту же операцию с исходным профилем и релизом.
8. Дождитесь результата App, DB и Workers и отдельного результата AI. Ошибка AI не отменяет успешную установку основного стека. Для AI используется готовый драйвер GPU либо CPU; Manager не устанавливает драйверы.

В этом комплекте офлайн-зависимости включены для Ubuntu 22.04, Ubuntu 26.04 и RHEL 9, а также Windows Server 2019/2022/2025 x64. Пакетов Debian и Ubuntu 24.04 именно в этом комплекте нет. ОС, обновления ОС, SSH, драйверы GPU и внешние инженерные приложения подготавливаются заранее.

Инструкции по бэкапу и очистке — CHANGES-0.5-RU.md. Модели и установочные файлы в бэкап не входят. Локальные профили хранятся в data, журналы — в logs рядом с Manager. Сохраняйте исходный complete ZIP для восстановления резервной копии.
