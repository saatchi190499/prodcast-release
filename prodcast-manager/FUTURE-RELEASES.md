# Manager 0.3.2: отдельный архив Ollama

Новый контракт minimum_manager=0.3.2: offline.external_ollama задаёт name, bytes и sha256 ZIP. В ZIP строго два файла: offline.ollama_runtime и offline.model_archive; их SHA256 остаются в artifacts основного manifest. Manager проверяет и распаковывает их в отдельный cache только на этапе AI. Веса модели остаются offline.external_model и отдельным файлом. Старые комплекты с Ollama внутри complete поддерживаются.

# Совместимость комплектов с Manager 0.3.1

Офлайн-комплект v0.4: profile=prodcast-five-vm-v3-offline, schema=3, minimum_manager=0.3.1. Карта offline.linux_packages включает rhel:9; для RHEL 9.x Manager выбирает один локальный RPM-репозиторий. Установочные проверки этой сборки отложены. App и Worker имеют исходную версию v0.3.1-rc.1.

Адаптер Workers 3–16 разрешён также для нового архива v0.3.1-rc.1 с SHA256 a7d370571eb0355951fb4bb0019e21cf6e7813dfa397bd6ee2374805de7f0b79. Исходный service_runner сравнен с адаптером: отличается только диапазоном номеров. Запуск этой сборки Workers пока не проверен.

Новый контракт: profile=prodcast-five-vm-v2, schema=2, minimum_manager=0.2.0, python=3.14.7, database_major=18, migration_policy=forward-only. Поле upgrade_from перечисляет допустимые исходные версии. Поддерживается версия вида v0.3.0-rc.1.

Комплект содержит App (deployment и backend/frontend/gateway), Worker, Agent и необязательный AI. Сервер активации в него не входит. Приложение получает только клиентский токен/доверенный CA либо подписанный офлайн-файл/публичный ключ. Проверка прав не отключается.

Для обновления нужны исходный профиль, завершённая предыдущая операция и проверенный SHA256 manifest. Manager сохраняет существующие пароли, сертификаты и идентификаторы. Старый адаптер v1 сохранён для прежних комплектов и незавершённых операций. Новые комплекты v2 не развёртывают встроенный сервер активации.

Перед миграциями создаются резервные копии; сбой резервного копирования блокирует дальнейшие шаги. Автоматического отката БД нет. AI устанавливается последним и ведёт отдельный журнал.

Смена контрактного поля не доказывает совместимость. Необходимы проверка пакетов, тесты адаптера и отдельная приёмка установки/обновления на целевых VM.

## Переменное количество Workers

Manager допускает 1–16 последовательных ролей worker1…worker16. Для asset Worker v0.3.0-rc.1 с SHA256 68a8ca761fe02fe0c8899b8e05823c787f661cba7ccd59ba83c8a7427014cd3e встроен адаптер: проверки номера в установщике и обработчике запуска расширены до 16; сам подписанный manifest и архив релиза не изменяются. На целевой VM обработчик компилируется установленным Python релиза. Будущие Worker-пакеты должны нативно поддерживать указанные номера и объявлять management.maximum_workers в manifest. Для неизвестных пакетов без этого контракта лимит — два.

Количество Workers фиксируется при создании установки. Автоматическое расширение уже установленной площадки в этой версии не поддерживается.
