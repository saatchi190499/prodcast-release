# Manager 0.6

## Добавление Workers после установки

1. Сделайте резервную копию всей папки профиля. Откройте исходный установленный профиль в Manager 0.6 вместе с его хранилищем доступа.
2. Выберите полный пакет **точно того релиза ProdCast, который сейчас установлен**. Новая версия Manager не требует обновления самого ProdCast.
3. На вкладке «Серверы» увеличьте количество Workers (всего до 16). Заполните новые адреса и SSH-доступ, подтвердите отпечатки серверов. Каждому новому Worker нужна отдельная подготовленная Windows Server VM.
4. Нажмите **«Добавить Workers…»**. Не используйте для этого обычное сохранение или «Обновить».

Manager проверяет установленный App, DB и прежние Workers, создаёт отдельные пароли и ограниченные права новым Workers, дополняет PostgreSQL/Redis и сетевой доступ, устанавливает новые службы и проверяет их готовность. App, прежние Workers и контейнеры БД не перезапускаются. AI не затрагивается. Идентификатор установки, ключи, сертификаты, активация и старые секреты сохраняются.

При сбое повторите «Добавить Workers…» с тем же релизом и адресами. Журнал и профиль удалять нельзя. После начала изменений разрешено только продолжение исходной операции. Если отказ произошёл только на предварительной проверке, можно исправить адреса новых VM или выбор релиза. Частично добавленные учётные записи не удаляются автоматически; их доступы сохраняются для продолжения.

До окончания операции не переносите профиль на другую машину и не запускайте другие операции. После завершения переносите обновлённый профиль целиком. Старый снимок профиля без добавленных Workers использовать нельзя. Расширенный профиль требует Manager 0.6 или новее; обратный переход на старый Manager не поддерживается.

Ограничения: только добавление последовательных Worker-номеров; удаление, перенумерация и смена адресов существующих VM не входят в эту операцию. Пакет Worker должен поддерживать требуемое количество. Проверка готовности службы не заменяет приёмочный запуск реального задания на новом Worker. Нагрузочный лимит БД не увеличивается автоматически.

CLI: `prodcast-manager-cli.exe add-workers --site <исходный-site.json> --workers-site <новый-site.json> --release <полный-релиз> --manifest-sha256 <доверенный-хэш> --yes`. Новый JSON должен содержать прежние настройки и дополнительные Workers; пароли запрашиваются отдельно.

## Совместимость Ollama components

Архив может иметь имя предыдущего релиза, другие ZIP timestamps или способ сжатия. Проверяются SHA-256 и размеры обоих внутренних файлов по доверенному манифесту выбранного релиза. Имена внутренних файлов могут отличаться: Manager сопоставляет их по содержимому и использует актуальные имена.

Это не отключение проверки целостности: изменённые файлы, лишние элементы, дубликаты, ссылки и небезопасные пути отклоняются. Совместимы только архивы с теми же внутренними байтами. Файл модели AI проверяется отдельно, как и раньше.
