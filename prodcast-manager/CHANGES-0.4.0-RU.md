# ProdCast Manager 0.4.0

Локальная сборка для стека App, Agent, Worker и AI из тега v0.5.0-rc.2. Публикация не выполняется.

## Файлы установки

В «Установка и обновление» выберите complete ZIP и укажите SHA256 файла release-manifest.json. ZIP уже содержит Ollama и системные зависимости для платформ, перечисленных в manifest. Разбивать архив больше 2 ГБ не нужно. Если выбран AI, в третьем поле укажите файл модели Qwen3 4B Instruct. Во втором поле можно выбрать отдельный архив Ollama для релизов, в manifest которых он указан как внешний. Для complete ZIP со встроенной Ollama это поле оставьте пустым.

## Доменный вход

В «Площадка → LDAP / Active Directory» включите «Включить доменный вход в App». Укажите LDAPS-адрес контроллера, домен пользователей, Base DN и DN группы допуска. Загрузите публичную цепочку CA контроллера, если она внутренняя. Сертификат сайта App/PFX для этого не подходит. Без загруженного CA App использует доверие своего контейнера; доверие Windows-ПК не передаётся автоматически.

Служебная учётная запись нужна для диагностических проверок Manager. App проверяет пароль и группу с правами входящего пользователя. Пароль пробного пользователя не сохраняется, пароль служебной учётной записи не передаётся в App. Проверьте подключение и пробного пользователя, сохраните настройки, затем выполните «Установить» или «Обновить». При сохранении настроек сервер ещё не меняется. LDAP-параметры хранятся в БД App и доступны в его админке; последующее обновление через Manager применяет сохранённые в Manager настройки повторно.

Для «Поиск пользователя в AD» обычно подходит userPrincipalName. Если UPN в AD не заполнен, выберите sAMAccountName. App VM и контейнеры должны разрешать DNS-имя контроллера через внутренний DNS; Manager не меняет DNS автоматически.

Вложенные группы поддерживаются. Допуск через основную группу AD не учитывается: используйте отдельную группу ProdCast. В теге App v0.5.0-rc.2 изменение группы или отключение пользователя не перепроверяется для уже открытых сессий. Эта сборка Manager не добавляет такую перепроверку.

## Выгрузка и восстановление данных

«Выгрузить бэкап…» сохраняет один файл .pcbackup в выбранную папку на ПК. Придумайте пароль минимум из 12 символов и сохраните его отдельно. Копия зашифрована; без пароля она не открывается.

Внутри — дамп основной PostgreSQL БД, пользовательские файлы App, конфигурация App и данные площадки с ключами шифрования. Пользовательские вложения включаются даже если они большие. Модели Ollama, Docker-образы, установщики, кэш AI, исполняемые файлы Workers и SSH-пароли в копию не входят. Интеграции, хранящие данные вне управляемых БД и тома media App, требуют отдельного резервного копирования.

Для согласованной копии Manager приостанавливает сайт и планировщик, ждёт завершения очередей и останавливает Workers и App. После выгрузки возвращает ранее работавшие контейнеры и службы.

«Восстановить из бэкапа…» заменяет данные существующей установки. Нужны исходная площадка и точный complete-релиз из копии. До изменений проверяются пароль, целостность, Installation ID, ключи и версия. На VM создаётся страховочная копия. Если восстановление прервалось, App и Workers остаются остановленными: устраните причину и повторите восстановление из того же файла. Автоматического отката БД нет.

Если папка Manager потеряна, выберите «Импорт профиля из бэкапа…», введите пароль и заново укажите SSH-доступ. Импорт создаёт новую локальную папку и сам не меняет VM. Для очищенных VM сначала выполните «Установить» с исходным complete-релизом, затем «Восстановить из бэкапа…». Сохраняются исходные адреса, Installation ID и лицензия. Перенос на другую топологию и восстановление сразу в другую версию этой функцией не выполняются. После восстановления можно отдельно обновить стек.

## Очистка VM

«Очистить VM…» предлагает два режима:

Очистка останавливает выполняемые задания. Если служба Worker не завершает работу штатно, Manager проверяет принадлежность процесса выбранной установке и завершает только его дерево процессов. Автоматический перезапуск службы на время очистки отключается. После ошибки повторите тот же режим очистки.

- **Пересоздать компоненты, сохранив данные:** удаляет управляемые контейнеры и регистрацию служб Workers. БД, файлы App и модели сохраняются. Затем используйте «Восстановить» с точным установленным релизом; для прерванной первой установки повторите исходную установку.
- **Полный сброс:** удаляет контейнеры и рабочие данные ProdCast, включая БД, файлы App и модели AI. Требуется ввод имени площадки. Затем можно выполнить «Установить» заново. Исходный профиль Manager и его лицензия остаются на ПК.

Это сброс установки ProdCast, а не переустановка ОС. ОС, сеть, SSH, Docker/Python, системные настройки и уже созданные резервные копии на VM сохраняются. Удаление резервных копий не входит в полный сброс. Чужие контейнеры и службы не удаляются. Включённые в профиль VM проходят проверку принадлежности установке до начала очистки.

Скопировать .pcbackup на другой ПК можно обычным способом. Храните его и пароль раздельно; не публикуйте копию вместе с установочным комплектом.
