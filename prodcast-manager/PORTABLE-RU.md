# ProdCast Manager 0.2.5 — portable

## Новая установка

1. Распакуйте весь ZIP в доступную для записи папку. Запустите `ProdCast-Manager.exe`. Папка `_internal` обязательна; EXE отдельно не переносится.
2. Выберите количество Workers (1–16) и укажите IPv4 для App, DB и выбранных Workers. AI заполняется только при включённой галочке. Укажите, SSH-пользователей, ключи либо пароли. Сверьте и сохраните SSH-отпечатки через «Пароли / ключ сервера». Пользователю Linux нужны root или sudo, Windows — права администратора.
3. На вкладке «Площадка» проверьте адрес App, IP рабочего ПК администратора, компанию и параметры лицензии. Для новой установки внутренний адрес App обычно `https://IP_APP`. Домен из PFX указывается отдельно на вкладке сертификата.
4. При необходимости импортируйте PFX с паролем. Для новой площадки отдельный пароль хранилища не нужен.
5. Выберите полный релиз, например v0.3.0-rc.1, нажмите «Проверить доступ», затем «Установить». Укажите SHA256 manifest из публикации релиза.

Данные доступа создаются и сохраняются автоматически в `prodcast-data`. Изменение набора адресов или ID площадки выбирает отдельную папку профиля. «Новая площадка» очищает поля для другого клиента, сохраняя файлы предыдущей установки. Для возврата откройте нужный `prodcast-data/sites/.../site.json`.

Изменение существующих серверов уже установленной площадки не считается их автоматической миграцией. Если VM принадлежат другой установке, Manager сохраняет защиту от перезаписи. Для обновления открывайте профиль именно этой установки.

## Необязательный AI — последнее действие

На вкладке «Серверы» появилась галочка «Установить AI». Для прежних профилей она включена, чтобы сохранить прежнюю настройку. Её изменение не создаёт новую площадку и не меняет пароли или CA.

Сначала Manager выполняет установку/обновление DB, App и выбранных Workers, проверяет их работу, запускает планировщик и фиксирует успешное завершение основного стека. Только затем подключается к AI, устанавливает зависимости, контейнеры и модель и проверяет ответ AI из App.

Ошибка SSH, установки модели, резервного копирования AI или проверки его ответа становится предупреждением AI. Успех основного стека сохраняется. Основной журнал — `journal.json`, отдельный журнал AI — `ai-journal.json`; общий отчёт содержит оба результата. Ошибки основных сервисов по-прежнему останавливают их развёртывание.

Если галочка снята, Manager не подключается к AI и не проверяет его доступность или файлы релиза. При следующей установке/обновлении в App устанавливается `PRODCAST_AI_ENABLED=false`. Уже работающие службы и данные AI не удаляются. Одно переключение галочки без установки/обновления не изменяет серверы.

При выключенном AI его строка неактивна и адрес можно не заполнять. Для последующего добавления AI укажите его адрес и SSH-доступ в том же профиле и выполните «Обновить» с тем же релизом. Идентификатор установки и доступы основного стека сохраняются.

Для повтора неудачного этапа выберите исходный релиз и нажмите «Повторить AI». Это не запускает миграции, остановку Workers или перезапуск App. Основная установка должна быть завершена с включённой галочкой AI. Если она завершалась с выключенным AI, сначала включите галочку и выполните обычное обновление для настройки App. Незавершённый AI с уже начатыми серверными шагами продолжается со своим исходным релизом; другой релиз не подменяет его журнал. Это ограничение не мешает обновить основной стек.

«Проверить доступ», «Состояние» и «Резервная копия» также обрабатывают AI в конце; его сбой отражается отдельно. При выключенной галочке резервная копия AI не создаётся.

## Где находятся данные

Все постоянные данные Manager находятся рядом с EXE:

```text
ProdCast-Manager.exe
prodcast-manager-cli.exe
prodcast-data/logs/          журналы Manager и диагностика серверов
prodcast-data/manager.json   последняя открытая площадка
prodcast-data/sites/<id>-<hash>/
  site.json                адреса, параметры, относительные пути SSH-ключей
  secrets.json             зашифрованные данные доступа, CA и сертификат App
  secrets.key              автоматически созданный ключ к secrets.json
  ssh/                     копии выбранных SSH-ключей
  journal.json             состояние установки/обновления
  ai-journal.json           отдельное состояние необязательного этапа AI
  app-tls-journal.json      состояние применения сертификата
  history/                 резервные копии зашифрованных данных
  cache/                   распакованные релизы
Старые папки `data` и `logs` автоматически переносятся в `prodcast-data` при запуске новой версии.
```

Хранилище не привязано к Windows-пользователю или компьютеру. Переносите EXE вместе с `prodcast-data`: SSH-пути относительные, последняя площадка сохраняется относительно папки приложения. Релиз ZIP и исходный PFX можно выбрать с любого диска; они являются входными файлами. Для установки без доступа к исходному ZIP возьмите его с собой либо выберите уже распакованный релиз из cache. EXE собран в формате onefile и не требует соседней папки `_internal`.

**Папка содержит полный доступ к площадке.** secrets.key хранится рядом с secrets.json, поэтому шифрование не защищает от человека, получившего всю папку. Храните и передавайте её как комплект административных ключей. Не публикуйте рабочую папку вместе с дистрибутивом. Удаление secrets.key лишает Manager возможности открыть данные — нужен исходный ключ из резервной копии, а не новый.

Службы и журналы на удалённых VM остаются в серверных каталогах `/opt`, `/var/lib` и `C:\ProgramData`: portable относится к управляющему приложению на ПК.

## Импорт из Manager 0.1.9 и ниже

1. Завершите текущую операцию и закройте прежний Manager.
2. В новом Manager нажмите «Открыть site.json» и выберите старый файл площадки, в том числе из `%LOCALAPPDATA%\ProdCastManager`.
3. Manager скопирует состояние, журналы, историю и SSH-ключи в свою папку. Исходная площадка не изменяется. Старый cache не копируется — выберите исходный релиз ZIP при продолжении.
4. При первом обращении к секретам введите прежний пароль vault. Он нужен один раз: секреты перешифровываются случайным локальным ключом без изменения installation ID, паролей служб и CA. Старый vault.json остаётся копией для восстановления; введённый пароль не сохраняется.
5. Если была прерванная установка, выберите тот же релиз и нажмите «Установить». Не начинайте обновление вместо продолжения установки.

Неверный пароль импорта не заменяет существующий vault и не создаёт новую установку. Если профиль уже импортирован, открывайте его из prodcast-data/sites — повторный импорт поверх данных запрещён.

При первом запуске новая версия переносит старые папки `data` и `logs` в `prodcast-data`. Совпадающие файлы не перезаписываются; конфликтующие профили остаются в старом `data` для ручной проверки. Для ручного переноса Manager должен быть закрыт.

## Допускаемые ОС

| Роль | ОС, amd64/x64 |
|---|---|
| App, DB, AI | Ubuntu Server 22.04, 24.04, 26.04 LTS; Debian 12, 13 |
| Worker 1 и 2 | Windows Server 2019, 2022, 2025 |

Linux требует systemd, apt, Python 3.10+ и SSH. Docker и Compose устанавливаются из официального репозитория соответствующего дистрибутива. Ubuntu 22.04 поддерживается штатным Python 3.10, без требования tarfile.extractall(filter=...).

Наличие GPU не блокирует установку AI. Ollama использует доступный GPU либо CPU; CPU работает медленнее и также требует достаточно RAM для модели. Опция установки NVIDIA-драйвера включена по умолчанию для новой площадки и может быть отключена. На Ubuntu Manager использует ubuntu-drivers, а без обнаруженного GPU устанавливает доступный серверный пакет драйвера из репозитория. На Debian требуются включённые contrib/non-free/non-free-firmware либо заранее установленный драйвер. Если нужна перезагрузка/Secure Boot, установка продолжится с доступными вычислениями, без требования работающего nvidia-smi. Пакеты устанавливаются без интерактивных вопросов debconf, MOK и needrestart; Secure Boot не отключается и ключ автоматически не регистрируется. Для активации GPU с Secure Boot администратору может потребоваться зарегистрировать ключ через консоль VM и перезагрузить её. Существующие конфигурационные файлы пакетов сохраняются, если пакет не предлагает однозначного действия по умолчанию. Ошибки apt не скрываются. В журнале отображается текущая стадия AI: драйвер, контейнеры, скачивание Ollama, модель, генерация. На Debian установщик не переписывает системные apt-источники для включения non-free. После проброса GPU и подготовки драйвера перезапустите Ollama; принудительный CPU-режим не устанавливается. Работоспособность генерации и готовность AI API по-прежнему проверяются.

Список допускаемых ОС основан на совместимости зависимостей, а не на выполненном полном деплое каждой комбинации. На текущих dev VM проверены Ubuntu 22.04.5 и штатный Python 3.10.12; App, DB и AI прошли preflight. На AI нет видимого NVIDIA GPU — это больше не блокирует установку. Полный деплой Debian и Windows Server 2019 этой версией ещё не проверен.

Ubuntu 20.04 исключена из текущей матрицы Docker, Debian 11 завершила обычную LTS-поддержку 31.08.2026; Windows Server 2016 не включена из-за текущей матрицы Python 3.14. Источники: [Docker Ubuntu](https://docs.docker.com/engine/install/ubuntu/), [Docker Debian](https://docs.docker.com/engine/install/debian/), [Debian LTS](https://www.debian.org/News/2026/20260712), [Python Windows](https://docs.python.org/3.14/using/windows.html).

## Проверка и CLI

`prodcast-manager-cli.exe self-test --gui-smoke` проверяет ресурсы, PFX и запуск интерфейса без соединений с серверами. CLI по умолчанию использует последнюю portable-площадку; `--site` позволяет открыть/импортировать другой профиль. Для новых площадок пароль не запрашивается. Для старого vault он нужен только при импорте.

Восстановление: см. [RECOVERY-RU.md](RECOVERY-RU.md). Для завершённой установки используйте **Восстановить** с установленным релизом; для прерванной повторите исходную операцию.
